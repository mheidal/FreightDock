# FreightDock: technical description

FreightDock is a Whiskerwood mod that moves goods between islands in bulk. The player pairs two Freight Docks. Each dock's ship then:
1. loads what the partner's warehouses are short of;
2. sails to the partner along a planned water route;
3. delivers into the partner dock's cargo, for the partner's workers to unload;
4. sails home.

The player-facing description is the top-level `README.md`. This file covers how the mod works.

**Status:** version 1.0 (`Content/Mods/FreightDock/FreightDock.uplugin`, UE 5.8). Pairing is one-to-one. Many-to-many links were investigated and tabled; see [Many-to-many links.md](Many-to-many%20links.md).

## Assets

All the mod's assets are in `Content/Mods/FreightDock`:

| Asset | Role |
|---|---|
| `BP_Startup` | Runs at the first main-menu load: registers the building, the Mod Options and the Stevedore modifier |
| `BP_MapLoad` | Everything in a loaded colony |
| `navaldock_freight` | The Freight Dock building: a child of `navaldock_trade`, with the trade dock's look |
| `WBP_FDToast` | On-screen messages: a paper background, a grey rounded rim and gold text, stacked below each other |
| `WBP_FDDeliverButton` | The "Deliver now" button in the dock window |
| `Route/SM_RouteStrip`, `Route/M_RouteLine` | The mesh and material of the route line, also used for the debug cell overlay |

Most graph functions are generated by the `fdgen` package in `Tools/FreightDock` and installed with `python -m fdgen.install`; see `Tools/FreightDock/README.md`.

These are built by hand in the editor: the Event Graph, Toast, StockpileToString, CollectionToString, LogDocks, LogKey and the widgets.

## Registration (BP_Startup)

- **Building:** `RegisterFreightDock` adds a `freightDock` row to `GridActors` and `BuildingIcons` (ModAPI's names for `GridactorDefs_Sync` and `Icons_Buildings`). The row is copied from the trade dock (`navaltradeDock`), with the mod's own actor class, name and description. It adds the English strings and uses the trade dock's unlock.
- **Options:** `RegisterOptions` adds two entries to Settings → Mod Options:
  - **Pairing key** (`freightdock.pairKey`): F1–F10 or 0. Default F5.
  - **Depart after** (`freightdock.departAfter`): 120 s, 180 s, 240 s or Never. Default 120 s. It is how long a partly loaded ship waits before it sails.
- **Stevedore modifier:** `RegisterExtras` adds `mod.stevedore` to the AgentModifiers table: a copy of `mod.constructionyardWorker` with +10 carry capacity and no expiry. It also adds the modifier's strings.

## Runtime (BP_MapLoad)

### Events

| Event | Calls |
|---|---|
| BeginPlay | Store ModAPI, bind the delegates below, `ReadPairKey`, start the freight timer (`TickSeconds`) |
| `onLoadingFinished` | Collect `Docks` (every WorkDock) and `FerryDocks`, then `ScanNow` |
| `onBuildingSpawned` | `OnBuildingChanged`, which schedules a rescan |
| `onOptionChanged` | `ReadPairKey`, which reads both Mod Options |
| Freight timer | `FreightTick` (if `FreightEnabled`), then `SyncStevedores` |
| Event Tick (also while paused) | `DrawArcs`, `ScanTick`, `ShowRouteLine`, `PairKeyTick` |

`PairKeyTick` runs, in order:
1. `PairAtCursor`, when the pairing key was just pressed;
2. `StandInClick`;
3. `DeliverTick`.

### Pairing

**Storage:** a dock's pairing is stored in its own `WorkDock.activeTradePartnerId`, as `-2 - partnerBuildingId`. A value of `-1` means unpaired, so any value of -2 or below means paired. The game never sets values that low, and the field is saved with the colony, though it has no `SaveGame` flag. The mod has no save data of its own.

**Pairing key**, with a dock selected (`PairAtCursor`):

| Sequence | Result |
|---|---|
| Key on dock A, then key on dock B | A and B paired, and both routes planned |
| Key on dock A, then key on A again | "Pairing cancelled", nothing changes |
| Key on a paired dock A, then key with nothing selected | A unpaired (both ends) |
| Key on an unpaired dock A, then key with nothing selected | "Pairing cancelled" |
| Key with nothing selected and nothing pending | "Select a dock first" |

Only Freight Docks can be paired; that is what `IsFreightDock` checks.

### Loading

Every `TickSeconds`, `FreightTick` handles each paired dock whose ship is berthed:

- **Request:** the partner's warehouse deficits, minus what is already in the ship's hold and in the partner's dock cargo.
  - The deficits are the unmet requests of the partner's "Deliver to" buildings: `StockpileLinker.m_destStockpileIds`.
  - The request is written to the dock's `m_requiredEmbarkSupplies_dockSpecific`, its live requirement and its input slots, so the dock's workers fetch those goods.
- **Freight:** every requested resource is recorded in `Requested` as `"<dock id>|<resource>"`. Freight is whatever is in the hold that was requested for this trip, or that the partner currently wants.
  - Ship provisions (canned food) aren't freight unless the partner asked for them, so they stay aboard.
- **Stevedores:** workers in a freight dock's worker slots get the Stevedore modifier (`SetStevedore`). Anyone who stops working at one loses it (`SyncStevedores`).

### Departure

Once there is freight aboard, the ship leaves when any of these holds:
- the hold is at its cargo limit;
- nothing more is wanted;
- `MaxWaitSeconds` (the "Depart after" option) has passed since loading began.

"Never" is stored as 1e9 seconds.

When the ship leaves, loading is paused: the requests and the input slots' capacity are zeroed.

**Deliver now:**
- **Injection:** while a paired freight dock is selected, `InjectDeliverButtons` adds a `WBP_FDDeliverButton` below the food section of its "Load resources onto ship" panel (`ShipPreparationWidget`). The button goes into the nearest Vertical Box above `arcolist_food`. Injection runs for 30 frames after each left click, because a dock window may just have opened.
- **Pressing it:** `DeliverTick` polls the buttons (`IsPressed`, edge-detected). `DeliverSelected` then sets the dock's loading clock far back, so the next `FreightTick` sends the ship.
- **Feedback:** a toast says "The ship is under way" if it has already left, or "Nothing loaded yet".

### Voyage

The game's navigation can't be steered from Blueprint: routes are only set by the game's own launch, recall and mission code. The mod therefore uses a stand-in.

- **The real ship** stays berthed at home. It is hidden, and its collision is disabled so that it can't be hovered or clicked. Both the colony and the sea simulation keep treating it as berthed.
- **The stand-in** is a copy of the ship's zoomed-in model (its `zoomedActor` class). The mod moves it along a spline course at `ShipSpeed`, from the home berth to the partner's stand-off point, `StandOff` units out from the partner's berth.
  - **Turning:** at each end it turns in place at `TurnRate` until it faces along the course, or faces the waiting heading.
  - **Bobbing:** it bobs and rocks all the time (`BobHeight`, `BobPeriod`, `BobRoll`, `BobPitch`), offset per dock so stand-ins don't move in step.
- **On arrival** (`VoyageArrive`, phase 1), the freight moves from the real ship's hold into the partner's dock cargo (`m_stockpile_goodsFromSea`). The partner's workers unload it, which only works if the partner has a ship assigned: a dock without a ship has no workers.
- **The return:** after `DwellSeconds` (phase 2) the stand-in sails home (phase 3). It is then removed, the real ship is shown again, and loading resumes.
- **Fallback:** if the stand-in can't be spawned, the trip becomes a timer, with delivery `TripSeconds` after departure.

**Safeguards:**
- If the real ship leaves its departure berth during a voyage (launched, recalled or reassigned), the voyage is cancelled. The stand-in is removed, the ship is shown, and the freight stays aboard, to be delivered on a later trip from this dock.
- Delivery goes to the dock the stand-in visited, even if the pairing changed in the meantime.
- Voyages aren't saved. After a reload the ship is back home with its freight, which is recognised again if the partner still wants it.

### Routes

**Water map:** the map is a grid of 100-unit cells (`CellSize`), which is 2 game tiles. A tile is 50 units, centred at `tile * 50 + 25`.

| Map | Holds |
|---|---|
| `Blocked` | Land cells (terrain blocks above water) and building cells |
| `Penalty` | Near-shore cells: passable, but they cost more |

**Building cells:**
- **With grid tiles:** a building blocks the cells holding its full and floor tiles. These come from `GridActor.liveFootprint` (`ReadFootprint`), counting tiles at height layer 0 and above.
- **Without tiles:** it blocks its colliding bounds, or all its parts if none collide, provided they reach the surface.

**Route planning** (`PlanRoute`, `FindPath`):
- **Search:** A* over cells avoiding `Blocked`, with an octile heuristic and at most `MaxExpand` expansions.
- **Endpoints:** a route runs from the dock's stand-off point to the partner's. It is a straight line when the direct line is clear.
- **Clearance:** routes keep `ClearanceCells` away from the shore, except near either end, so that a ship can leave and reach its berth.
- **Storage:** the result goes into `RoutePts[Id*1000+i]` and `RouteLen[Id]`. Each dock has its own route toward its partner.

**Course** (`MakeCourse`): a voyage spline built from the route points.
- **Corners:** rounded, using `CornerRadius` and `CourseSpacing`.
- **Leaving and arriving:** each end gets a turn arc (`TurnArc`), so the ship leaves the berth pose and reaches the end pose without its heading jumping.
  - Each turn aims at the farthest route point in straight sight.
  - It tries `TurnRadius`, then `TightTurn1` and `TightTurn2` times that radius, turning in each direction.
  - If no arc stays clear of land, the ship turns in place instead.
- **Tangents:** set explicitly (`SmoothTangents`), so that unevenly spaced points don't make the spline bulge.
- **Fixed per trip:** the course is set at departure.

**Rescan:** blocked cells are rebuilt in slices across frames by `ScanTick`. Even while paused, a mass build costs one sliced rescan, not one per building.

| Phase | Work | Budget per frame |
|---|---|---|
| 1 | Terrain blocks | `ScanBudget` (500) block reads |
| 2 | Coast and penalty | `ScanBudget / 20` cells |
| 3 | Buildings | `ScanBudget / 50` buildings |
| 4 | Route check | One dock |

- **Route check:** in phase 4, each route that now crosses a blocked cell, or has none, is replanned (`RouteStillClear`). A route is also replanned whenever `Blocked` changed size, since a better one may exist.
- **When it runs:**
  - about a second after a building spawns (`OnBuildingChanged`);
  - every `RescanSeconds` of real time;
  - in one go at load (`ScanNow`).

### Display

- **Pair arc** (`PairArcs`): while a paired dock is selected, an arc in pale lavender (`PairArcColor`, height `PairArcHeight`) is drawn between it and its partner.
- **Route line** (`DrawRoute`, `ShowRouteLine`, `BuildRouteLine`): the course of the selected dock's ship, as flat spline meshes (`RouteLineWidth`, `RouteLineHeight`, `RouteLineColor`). Which course is shown depends on the ship:

  | Ship | Course shown |
  |---|---|
  | Sailing | The voyage spline |
  | Berthed | The outbound course (`PreviewCourse`, cached until the route changes) |
  | Waiting at the partner | The homeward course |

- **Stand-ins** (`DrawArcs`):
  - **Hover:** hovering a stand-in (within `HoverRadius`) shows its current course as the route line, plus an arc to where it's heading and one to its home dock. The voyage arc is also shown while its dock or partner is selected.
  - **Click:** clicking a stand-in pans the camera to its home dock (`StandInClick`). It doesn't select the dock, because writing the game's selection doesn't open the dock's window.
- **Toasts** (`Toast`, `WBP_FDToast`): short messages from pairing and Deliver now. New toasts stack below existing ones. Arrival and departure toasts were removed.

## Keys

| Key | Does |
|---|---|
The pairing key (Mod Options, default F5) is the only key bound in a release build.

These debug functions stay in BP_MapLoad but aren't bound to any key. Some docstrings mention F3 and F10, but the Event Graph binds neither. To use one, hook it to an Input Key event while debugging:

| Function | Does |
|---|---|
| `DebugCells` | Add it to `PairKeyTick` (after `StandInClick`); F7 then toggles an overlay of the route map around the camera's focus, redrawn once a second: land cells in `LandCellColor`, building cells in `BlockedCellColor`, near-shore cells in `PenaltyCellColor`, `CellsRadius` cells each way |
| `LogPlans` | Every player ship's plan, berth and motion |
| `LogLinks` | Each dock's partner and its "Pick up from" / "Deliver to" buildings |
| `LogDocks` | Docks, ferries, nautical berths and ships |
| `LogNauticalDocks` | Every nautical dock's IDs, ship count and location |
| `LogFootprint` | A building's grid footprint cells and occupancy |
| `DebugSetup` | Unlocks the trade dock and grants planks, bricks and canned food |
| `ScanNow` | A full rescan at once |

**Log file:** `%LOCALAPPDATA%\Whiskerwood\Saved\Logs\modlog.txt`. Generated log lines are prefixed by `Stamp` (`[yyyy-mm-dd hh:mm:ss] `); hand-built functions use ModAPI's timestamp.

## BP_MapLoad tunables

Defaults are as set on the class.

| Variable | Default | Purpose |
|---|---|---|
| `TickSeconds` | 5 | Freight logic interval (game time) |
| `MaxWaitSeconds` | 120 | Partial-load wait; overwritten by the "Depart after" option |
| `TripSeconds` | 30 | Fallback trip time (no stand-in) |
| `FreightEnabled` | true | Master switch for the freight timer |
| `ShipSpeed` | 100 | Stand-in speed, units per second of game time |
| `TurnRate` | 45 | Turn-in-place speed, degrees per second |
| `DwellSeconds` | 5 | Stand-in wait at the partner |
| `StandOff` | 200 | Stop distance out from a berth |
| `HoverRadius` | 300 | Hover / click distance for a stand-in |
| `BobHeight`, `BobPeriod`, `BobRoll`, `BobPitch` | 3, 5.5, 2, 1 | Stand-in bobbing (units, seconds, degrees, degrees) |
| `CellSize` | 100 | Route cell size |
| `ClearanceCells` | 1 | Distance kept from the shore, except near the ends |
| `MaxExpand` | 20000 | A* expansion limit |
| `CourseSpacing` | 200 | Spline point spacing |
| `CornerRadius` | 500 | Corner rounding |
| `TurnRadius`, `TightTurn1`, `TightTurn2` | 300, 0.6, 0.35 | Turn arc radius, and the tighter fallbacks as fractions of it |
| `RescanSeconds` | 20 | Periodic rescan interval (real time) |
| `ScanBudget` | 500 | Rescan work per frame |
| `ArcColor`, `ArcWidth`, `ArcHeight` | gold, 2, 0.1 | Voyage arcs |
| `PairArcColor`, `PairArcHeight` | (220, 196, 255), 0.15 | Pair arc |
| `RouteLineColor`, `RouteLineWidth`, `RouteLineHeight` | gold, 12, 5 | Route line |
| `CellsRadius`, `LandCellColor`, `BlockedCellColor`, `PenaltyCellColor` | 25, … | Debug cell overlay |

These hold state rather than settings:
- **Docks and pairing:** `Docks`, `FerryDocks`, `PendingDock`.
- **Loading:** `LoadingSince`, `DepartedAt` and `Requested`.
- **Voyages:** `Voyages`, `VoyageShip`, `VoyageSpline`, `VoyageDist`, `VoyagePhase`, `VoyageWait`, `VoyageBerth`, `VoyagePartner` and `VoyageEndFwd`. These are keyed by dock building ID; the phase is 1 out, 2 waiting, 3 home.
- **Route map:** `Blocked`, `Penalty`, `RoutePts`, `RouteLen` and the `Scan*` variables.
- **Display caches:** `RouteCurves`, `PreviewCourses` and `Shown*`.
- **Deliver now:** `DeliverBtns` and `InjectFrames`.

`Tools/FreightDock/tests/blueprint_vars.json` lists every variable with its type.

## Known limitations

- A course is fixed when the ship departs. A replan mid-voyage applies from the next trip.
- Each ship carries freight one way, and the return trip is empty. Two-way traffic uses each dock's own ship.
- Launching, recalling or reassigning a ship mid-voyage cancels the voyage. The freight stays aboard.
- Both docks need a ship, even for one-way freight. A dock without a ship has no workers, so goods delivered to it aren't unloaded.
- Ships always request canned food (provisions), and the mod can't turn that request off.
- A dock's "Pick up from" list isn't considered when building the request (`m_sourceStockpileIds` isn't read). Goods the dock's workers can't fetch stay requested. The ship then sails once it's full or the "Depart after" time has passed, not when "nothing more is wanted".
- The dock uses the trade dock's model.
