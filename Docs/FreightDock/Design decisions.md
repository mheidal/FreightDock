# FreightDock: design decisions and expected behaviour

Source: full chat history 2026-10-26 .. 2026-11-09. Dates are of the deciding message. "(uncertain)" marks anything not clearly settled. Later entries override earlier ones; replaced behaviour is noted briefly.
Predecessor: the mod began as "FerryFreight" (2026-10-27, feasibility test, folder Content/Mods/FerryFreight); renamed FreightDock 2026-10-31. Branches: `freightdock` (released 1.0 / 1.1 work), `freightdock-networks` (networks/dispatch, current), `freightdock-packed-links-spike` (spike only), `feat/suzie-force-writable` (Suzie patch). Latest known commit: b4d320e (2026-11-08); later work uncommitted at end of history.

## 1. Concept, origin and what the mod can/cannot do
- 2026-10-26 Problem: vanilla workers move goods between islands 10 at a time by ferry. Goal: bulk interisland freight. The Mod API cannot change worker behaviour; user accepted "workers load a warehouse/dock part, mod makes the trip when as full as it'll be, unload on the far side".
- 2026-10-27/28 Proven mechanism: a nautical (work) dock with a docked, crewed ship; the mod writes the dock's `m_requiredEmbarkSupplies_dockSpecific` (the only requirement field the game does not rebuild/wipe); the game's stevedores carry goods into the ship's hold; the mod moves hold contents (`NauticalShipState.cargo`) into the target dock's `m_stockpile_goodsFromSea`; the target dock's workers (needs an assigned ship, otherwise no workers) carry it to warehouses. Needs Suzie `ForceBlueprintWritable` entries in Config/DefaultEditor.ini (editor restart, no recompile).
- 2026-10-28 Ship hold size (cargoLimit) caps load per trip (scout ~11, user's ship 89, biggest ~400). Dock requests are not saved; mod re-applies after load.
- 2026-10-28/29 Moving real ships failed (plan/assignedDock/state writes cannot launch a berthed ship; the colony-side work dock owns berthed ships). Ferry docks must NOT be used ("I'd really prefer to avoid having the ferry docks used for anything but routing", 2026-10-28; reluctance because workers would use freight ferries, 2026-10-30).
- 2026-10-30 Decision: visual proxy ("stand-in") ship: copy of the real ship's zoomed-in actor sails from A to B while the real ship stays hidden at its berth; real ship's collision is disabled while hidden (2026-11-02).
- 2026-10-31 Own building "Freight Dock": child of `navaldock_trade` (`navaldock_freight`), registered at first main menu by BP_Startup (rows in `GridActors`, `BuildingIcons`, `Strings`, `unlocks`, `Toolbar`), shown in seafaring docks toolbar with trade dock icon/model. A freight dock both sends and receives and has its own ship; no tender ship (see section 13).
- 2026-11-04 Freight Dock has its own tech `unlock.freightDock`: Naval, tier 1, 89 science (same as Trade Dock), no prerequisite (user), sort order 35 (after Trade Dock 30, before Storage Dock 40). A hidden small-shipyard prerequisite was copied from the Trade Dock (kept: user 2026-11-09 "fine"). Existing saves must research it separately. Verified buildable after research (2026-11-04 20:44).
- 2026-11-07 Test confirmed freight dock's `activeTradePartnerId` use does not interfere with trade docks (trade dock UI showed only the discovered trade island).
- 2026-11-04 A custom 3D freight dock model would need no modelling (kitbash game pieces, ~1-3 days); not done; Freight Dock still uses trade dock model/icon.

## 2. Networks (replaced one-to-one pairing)
- 2026-10-28..11-02 Original design was one-to-one pairing of two freight docks via hotkey F5 (select dock, press F5, select partner, press F5; stored in `activeTradePartnerId` as `-(2+partnerId)`; survives save/load). Pairing limited to freight docks (2026-10-31). Tested well incl. two pairs (2026-11-01).
- 2026-11-02 Many-to-many tabled once, then resumed 2026-11-04: slot-links (63 docks x 4 links) rejected as too small ("4 is simply not a very high number"); LTN-style network membership chosen (user noted it is Factorio LTN-like).
- Final model (2026-11-04..06): each freight dock belongs to up to 3 networks (user 2026-11-06: "drop the limit to three networks"); network IDs 1-31; per membership a role: provide, request, or both. A dock in 4 networks (old test layout) keeps 3 lowest. Providing requires at least one Input warehouse (the game's "Pick up from" list) (user 2026-11-04). Request-only docks never get jobs/never ship ("Idle: not providing"). A provider with no ship cannot work.
- F5 pairing, the pairing-key Mod Option and all pairing code REMOVED (2026-11-04/05, replaced by network GUI). Old 1.x pairs convert on load: each pair becomes the lowest free network with role "both" on both docks; a pair whose partner is gone becomes unpaired; log line "N 1.x pair(s) converted; colony data from version none". Migration tested OK (2026-11-06, 11-09). Converted docks without Input warehouses will not load (noted).
- 2026-11-05 Terminology: mod's own text says "Input" (= game's "Pick up from") and "Output" (= game's "Deliver to"); game's own labels unchanged. Headings "TARGET'S OUTPUT" and "THIS DOCK'S INPUT". 2026-11-06 global rename "partner" -> "target" (function TargetOf, variable VoyageTargetId); game field `activeTradePartnerId` keeps its name.
- Network colours: fixed per-ID palette "C" (user leaned C, 2026-11-08): ten colour families x three shades, networks 1-10 light, 11-20 mid, 21-30 deep, 31 white; red and blue excluded from network hues because pointer colours are red (providers, #E9594D) and blue (requesters, #71D0EA) (user 2026-11-05).
- Copy/paste (2026-11-08): Ctrl+C on a freight dock copies its networks (toast "Networks copied: ..."); Ctrl+V on another freight dock pastes them (toast "Networks pasted: ...", target's pause setting kept); Ctrl+Z straight after undoes ("Paste undone"; only until selection changes); Ctrl+C with a non-freight selection clears the copy; keys typed in the rename popup are ignored. Game's own Ctrl+C/V does not copy any mod data (probe 2026-11-04). Side effect: Ctrl+Z also toggles game's z-layer hotkey (accepted). User would have preferred "Copy settings"/"Apply settings" buttons in the network GUI, but accepted the keyboard version ("All bulleted tests pass").

## 3. Dispatch and jobs (global dispatcher replaced round-robin, 2026-11-05)
- Round-robin among requesters was built first, then dropped (user 2026-11-05 04:45: wanted "a smart global dispatch that assigned ships to jobs based on supply and need").
- A job = one provider ship's next trip: provider P, requester R, manifest of goods. One job per provider. Dispatcher runs every TickSeconds of game time (BPL_FDDispatch, Loom); jobs live in BP_MapLoad variables and are NOT saved across reload (goods aboard then count as supply).
- Demand per requester/good = Output warehouses' unmet requests (including Keep-empty warehouses: slot minHold - count - inbound) minus goods already unloaded at target minus what every pending job brings. Supply = Input warehouse free stock (each warehouse counted once per pass, so shared warehouses are not promised twice) plus leftovers at the provider's dock.
- Score = sum(units x (1 + age/tau)) / round-trip time; tau = 10 game minutes; trip time estimated from straight-line distance + allowance. User 2026-11-05: optimise goods delivered per unit time with a waiting bonus. Greedy global assignment, best pair first.
- Minimum load option (Mod Options): None / 25 / 50 / 75 / 90 % of the hold (share of the smaller of hold and what R wants P can supply, so small requests still qualify); waived when R's demand has waited longer than "Depart after"; with Depart-after = Never it is waived after 10 minutes.
- Manifest may grow while loading if the requester's need grows, hold has room and Input warehouses can supply (user 2026-11-05).
- A new job takes goods in this order: already aboard, the dock's delivered-goods store, then Input warehouse stock (2026-11-09; the store was last before).
- Input slot: haulers carry goods straight into the hold. The dock's input slot count is not goods but the game's bookkeeping for hauls under way (2026-11-09: it rose ~13 per trip while the input warehouse never lost stone, and fell back when the trip ended). Left stale (a trip cut off when loading stopped, or saved), it fills the slot and haulers get no room or turn back; each dispatch pass zeroes the count of a slot with no dropoff reserved (BPL_FDNet.ClearInputCounts). The user's rule "any extra goods in the dock ought to be in the delivered-goods store" stands, but the slot holds none: moving its count to the store created goods (the earlier ~250 -> ~1000 climb), so that was removed.
- Leftover/undelivered goods: moved from the hold into the dock's delivered-goods store ("waiting to unload"); a later job that wants them moves them straight into the ship's hold (no loading store, no `Parked` record - user declined the record, 2026-11-05). Ship must never hold non-job freight (user 2026-11-06 00:26); canned food (the game's own provisions) is exempt unless a job carries it.
- Cancellation: leaving a network (or a requester no longer wanting a good) mid-load cancels/shrinks the job; goods aboard go to the provider's delivered-goods store. Removing a dock from a network mid-voyage does not cancel: cargo is still delivered ("behaving as intended"). Target destroyed mid-voyage: ship finishes, cargo parked at home. Requester demolished mid-load: goods go to provider's waiting-to-unload. Docks with an assigned ship cannot be demolished.
- Stall rule: progress counts goods aboard and being carried (counting the input slot too was tried 2026-11-09 and reverted: it fed the request without end). A good with open request but no hauler pickup for 20 s is dropped from the job and not re-offered by that dock until its Input stock changes; a job left with nothing is cancelled.
- Ping-pong guard: a provider does not ship goods its own Output warehouses still request. Shared providers never both fill the same demand (tested 2026-11-06). Fairness verified (alternates between two requesters).
- Idle reasons (shown and, at the time, logged): "Idle: no ship at dock", "Idle: no requests for its inputs", "Idle: no input warehouses", "Idle: below minimum load (30 for X)", "Idle: not providing"; "Idle" and "Waiting for cargo" must never appear together (user 2026-11-06).
- Keep-empty: the game's deficit function returns nothing for Keep-empty warehouses; the mod computes their request itself; B's workers unload into a Keep-empty warehouse when it is the only Output target (tested, user 2026-11-03).

## 4. Loading, departure, pause, Deliver now, crews
- Request written to the game must be a TOTAL to have aboard (game subtracts the hold): request = exactly the job (or the hold if larger); intake space = request minus hold; goods no longer wanted get 0 allowance (fixed hauler turn-aways, confirmed 2026-11-04 02:52). Request capped at ship free space; with Input warehouses set each good is capped by their free stock (count - reservedForPickup); with none set, free space is shared proportionally between wanted goods.
- Departure rules: hold full, all manifest aboard ("all wanted aboard", remaining capped by what Input warehouses can supply), or the "Depart after" timer (counted from when loading started) - option values 120 s (default), 180, 240, Never. Ship waits up to 30 s for goods already being carried to arrive before leaving.
- Deliver now (button in the dock GUI Ship section): sails on the next check without waiting for haulers (2026-11-09: user wants it immediate); shows "Departing" (tooltip also "Departing"); normal wait shows "Waiting for final cargo"/"Leaving once haulers arrive". Disabled with reason tooltip when it cannot act ("Already under way", "Nothing loaded yet"). Goods still being carried are taken back by haulers (left as is).
- Pause/Resume (per dock, stored in bit 27): ship finishes current job and takes none; shows "Idle: paused"; pause icon from game (icons8 pause/play), placed right after "SHIP".
- Night/crews: docks have no overtime. A dock is on duty from the moment one of its workers is at the dock until nightfall. Off duty: no new jobs that need hauling (jobs made only of goods aboard/leftovers may still sail), stall and Depart-after clocks pause ("Crew off duty"), nothing dropped overnight; INCOMING says "Providers off duty".
- Bug fixed 2026-11-09: completed jobs did not clear the dock's request (paused dock loaded overnight); Complete now clears like Cancel.
- Canned food: every naval dock requires ~3-4 days of provisions for crew (game behaviour, not dockSpecific); provisions stay aboard and are not freight unless the target wants canned food.

## 5. Voyages, stand-ins, routing
- Stand-in sails visually; real ship stays berthed/hidden. Voyage: depart from berth along ship heading (arc), follow planned course, stop at the target's stand-off point (StandOff 200, the BP_MapLoad default as of 2026-11-09; set to 500 on 2026-10-30, later lowered), dwell 5 s (game time), return along inbound course and the real ship reappears. Delivery goes to the dock visited. Cargo is delivered on arrival (as fling animation lands). Goods appear at the destination; ship returns empty (mid-voyage reroute and empty-return improvements deliberately NOT implemented, user 2026-11-01 "2 and 3 are unnecessary").
- Voyage cancelled if the real ship leaves its exact berth (launched/recalled/reassigned); freight stays aboard. Reassigning the target's ship away means goods are delivered but cannot be unloaded until a ship is assigned (user accepted).
- Routing: water map from terrain blocks (land = block top above -50), blocked cells = land + building footprints (liveFootprint tiles full/floor; others by collision or full bounds; underwater buildings ignored) + dock/waterfront structure outlines + berthed ships (4 x 2 cell rect along heading, except route's own ends, re-checked at departure). A* on 50-unit cells (one game tile), ClearanceCells = 4 (200 units) as graded near-shore cost (40 per level), not a hard block; no diagonal corner cutting; exact grid-walk line checks. Blocked cells are never passable, including the route's own dock: "no exemption for ships being able to pass through their own docks. They should be able to reach their own berths, but not by actually passing through the dock itself" (user 2026-11-06). Search limit 80,000 cells.
- Course shaping: spline courses with rounded corners (CornerRadius 300, CourseSpacing 200), SmoothTangents, forward turning arcs at departure/arrival (TurnRadius 300, tries both directions and tighter radii 0.6x/0.35x, extra aim points every 200 units on first/last legs, full check against land/footprints/other docks/ships); if nothing fits the ship turns in place (user chose "turn in place" over backing out, 2026-11-01). Home stand-off point is not steered through; StandOffPoint picks a clear open-water direction (18 candidates) and logs when boxed in. TurnRate 90 deg/s.
- Stand-in bobbing (BobHeight 3, BobPeriod 5.5 s, BobRoll 2, BobPitch 1) approved. Facing: stand-in turns by its model's yaw offset from the ship (WSS Allhands model faces opposite way; its berthed heading comes from ship actor forward vector) - fixed and verified 2026-11-06.
- Rescan: map rebuilt at load, then on a REAL-time interval (RescanSeconds 20, works while paused - user: "The map can change while paused"), sliced across frames (500 blocks/frame); a building spawn schedules one rescan ~1 s later; routes replanned when blocked count changes; a course is fixed at departure (replan applies next trip). Docks' outlines rebuilt on load and when blocked-cell count changes.
- Rendering: route line drawn as spline meshes (SM_RouteStrip, M_RouteLine; RouteLineColor/Width 12/Height 5) for the selected dock showing outbound course when berthed/outbound and inbound course when at stand-off/inbound, only for that dock's own ship; hovering a moving stand-in shows its current route plus arcs to heading and home dock; clicking a stand-in pans the camera to its home dock (selection write dropped because the game panel did not open).
- Arc between docks: lavender pair arc (PairArcColor, height 0.15) when a paired dock selected - later replaced by network arcs/pointers (section 7).
- Unload animation (Loom BP_FDFling): each flying piece = 4 units, at least 1 per delivered good, max 36 pieces, 0.8 s flights, 0.07 s stagger, uses resource haul mesh, pauses with game, not shown on loading; cargo enters the target store as pieces land (user 2026-11-04 08:06: timing coincides well).
- Verified in game 2026-10-30..11-07: robustness cases, two-pair delivery, OQ and IQ routes ("looks perfect now").

## 6. Dock GUI (Loom panel WBP_FDPanel, shown for every selected freight dock)
- Native dock window parts hidden for freight docks: "Load resources onto ship" panel, supported-actions element, DEPARTURE CHECKLIST (EmbarkationPanel: crew, canned food, Send to sea) with SizeBox minimum heights cleared so no gap; restored for other docks. Panel placed left of the dock window, foot 8 px from screen bottom, ragged-paper background (26 px beyond outline) with squircle frame (RoundedFrameWithHeaderIcon, icon off), padding 20/16, 500 px wide, game fonts; invisible until placed.
- Header: the dock's name. NETWORKS line: one label per membership in ascending ID order, coloured, "1: provide", non-breaking joins, one per line wrapping; tooltip lists "Provider(s):" (red) and "Requester(s):" (blue) docks; Edit button opens the network GUI.
- SHIP section (holds the job description): clickable "Delivery to <name>" (pans camera), ship state (Waiting for cargo / Loading m:ss of m:ss / Waiting for final cargo / Crew off duty / On the way / Unloading / Returning / Departing), hold, one-way trip time (only with a job), Pause and Deliver now controls, "Dropped: 3 flax (no hauler)" notice until sail. MANIFEST (merged into SHIP, no separator, no header row, names on hover; goods names wrap): columns left to right Available to load, Reserved no hauler yet, On the way here, On the ship, Amount requested; only the job's goods. Hidden when no job.
- WAITING TO UNLOAD section (after SHIP): current contents of this dock's delivered-goods store as resource icons with counts, hidden when empty, counts drop as haulers take goods.
- INCOMING section (requesting docks): per wanted good: wanted/coming/from whom and ETA ("Loading at X" / "From X, ~1:20"); if nothing coming a single reason: no provider on its networks, no provider stock, providers busy, providers off duty, "Providers missing ships" (only providers lack ships, 2026-11-08), below minimum load (n of m), no route. Names wrap.
- Succinct UI text is a standing preference ("short fragments, not full sentences"). Per-dock/per-job information is shown only locally in the dock GUI; no colony-wide displays (user 2026-11-06). Toasts only for copy/paste/undo (2026-11-08) and the dev cheat.
- Toasts earlier: restyled like game work-dock window, stack downward, departure/arrival toasts removed (2026-11-01); later all toasts removed; copy/paste toasts added 2026-11-08.

## 8. Naming, signs and persistent storage
- Dock/network naming evolved: 2026-11-05 signs `[fd] Name` near the dock door and `[fn3] Food` named docks/networks with sign text hidden except on hover; REMOVED 2026-11-08 in favour of rename-in-place popups; signs are ordinary again.
- Rename: click dock title (dock GUI) or network ID cell -> popup WBP_FDRename centred over the click using the game's own text-entry widget (blocks hotkeys; Enter saves, Escape cancels, empty restores default "Freight Dock <id>", popup closes on deselect). Network shown as "3 Food". Names use capitals; popup must be dark blue with white text/size 16; runtime restyle of the box crashed the game.
- Storage facts: only `activeTradePartnerId` (int32 per dock) and colony event flags survive save/load. `activeTradePartnerId` stored value = -(2 + x): x below NetBase (2^22 = 4,194,304) = FreightDock 1.x dock ID; x >= NetBase = network value (range split chosen over a format bit, user 2026-11-07: "pleasing alternative"). Network value: 3 slots x 9 bits (5-bit ID 1-31 with 0 empty, 2-bit role written 00=both, 01=provide, 10=request, 11 read as both, 2 free bits), bit 27 paused, bits 28-30 free; ~8+ free bits kept deliberately unassigned. "Depart only when full" and network priority were removed entirely (user 2026-11-07).
- Event flags (`ArcoSystems.m_miscEventFlags`, a set of names, forced writable via DefaultEditor.ini - the only ini entry kept): entries `fd.<key>=<value>`; case is lost so capitals are escaped (`^`+lowercase); values cut to 60 chars. Stores dock names, network names and `fd.ver=1.1` (keep BPL_FDStore.Version() equal to .uplugin version). Developer confirmed 2026-11-09 the method will not be blocked and unknown flags are not whitelisted/cleared; he is ticketing a native per-save mod data slot. All fd.* data must be kept clean (delete/archive entries for deleted docks, networks, finished jobs) - task for later (user 2026-11-09). Flags could later hold jobs across saves, job history, ship positions.
- Rejected storage: sign text (unwritable), warehouse lists (read-only), fake request/store entries (lost on save, show in UI), profile save KV store (global per player, not rewinding; developer says GetSave+SetString stays but do not call Save), ship name tags (unreliable), tender approach.

## 9. Mod options, text, logging
- Mod Options (Menu -> Settings -> Mod Options): "Depart after" (120 s default, 180, 240, Never), "Minimum load" (None/25/50/75/90 %). Pairing key option removed. Option text keys `setting.FreightDock-<id>.name/.description`, registered by BP_MainMenuLoad (0.2 s after menu, again on language change).
- All player-facing text in one strings file BPL_FDText.lm, keys `freightdock.<area>.<item>`, English fallback; text_hook.py flags long/full-stop text; no strict word limit. Min-load description reworded to a short fragment.
- Log prefix `[FreightDock]` on every mod line; log text ASCII only (non-ASCII flips modlog to UTF-16). Routine log lines were removed in release prep (2026-11-07); kept: startup registration, 1.x migration, "ship left its berth", "no target", "no water route", stand-off boxed-in. Closing-bug diagnostic log line and the "Probe:" lines (temporary, hooked up by agreement) stay until release, then removed.
